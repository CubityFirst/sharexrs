# History harness

A headless .NET console app that runs **ShareX's own** history code
(`ShareX.HistoryLib.dll`, with ShareX's `Microsoft.Data.Sqlite`, `e_sqlite3`
and `Newtonsoft.Json` from the reference build) so `crates/sharex-history` can
be compared with it value for value. No window opens and nothing is patched;
internal members (`HistoryManager.Load`, `StatsFormat`, the charts' helpers,
`StatsWindow.GetRate`) are called by reflection. Like ShareX, it runs with
`System.Globalization.UseNls` (ShareX.runtimeconfig.json sets it), so
culture-aware sorting and matching are Windows NLS's.

It never touches a ShareX profile: everything is written under the work
folder you give it.

## Build and run

Needs the .NET SDK that builds ShareX (net11.0) and the reference build in
`G:/scripts/sharexrs-ref/ShareX-build` (override with `-p:ShareXBuild=<dir>`).

```
python tools/history-harness/make_cases.py tools/history-harness/cases.json
dotnet build tools/history-harness -c Release -o G:/scripts/sharexrs-ref/history-harness/bin
cargo run -p sharex-history --example harness -- G:/scripts/sharexrs-ref/history-harness/bin/HistoryHarness.exe tools/history-harness/cases.json G:/scripts/sharexrs-ref/history-harness/work [<a History.db to compare, copied first>]
```

The example runs `HistoryHarness sharex <cases> <work>` (ShareX's side, into
`<work>/sharex.json` and the `sharex*` files), then does the same with
ShareXrs, calls `HistoryHarness read` on ShareXrs's database and
`append`/`hold` for the concurrency checks, compares everything, writes
`<work>/report.md`, and exits non-zero on any difference. Dates depend on the
machine's time zone on both sides; the cases poke at GMT Standard Time's DST
edges (the checked-in fixtures were made there).

Commands of `HistoryHarness.exe`:

- `sharex <cases.json> <work>`: everything below, ShareX's side.
- `read <History.db> <out.json>`: ShareX loading a database (items, or the
  exception's type).
- `read-json <History.json> <out.json>`.
- `append <History.db> <item json>`: `AppendHistoryItem`, printing `ok <ms>`.
- `hold <History.db> <ms>`: holds a write transaction for that long after
  printing `locked`.

## What's compared

- **Reading ShareX's files:** History.db after `AppendHistoryItems` and the
  windows' edits (`Favorite`, `Tag`, a tags dictionary, `Edit`, `Delete`, an
  append after deleting the last id); a database with odd values inserted by
  SQL (every date form, `NULL`s, numbers and a blob in text columns, odd
  `Tags`); three databases whose load fails (`NULL` date, bad date, bad
  `Tags`); History.json written by `HistoryManagerJSON` in two appends and a
  hand-written old-style one; History.xml written by `HistoryManagerXML` and a
  hand-written one.
- **Writing:** ShareXrs writes the same items and edits; every stored value
  (with its SQLite type), the schema text, `sqlite_sequence` and the PRAGMAs
  must equal ShareX's database, and ShareX must read ShareXrs's database
  exactly as it read its own.
- **Migration:** both migrate both History.json files (`MigrateFromJSON`) and
  the databases must be equal; `migrate_history_file` in a scratch profile.
- **Queries and stats** over the two databases: the advanced panel's type and
  host lists and the process names (window code, copied, run with .NET's
  comparers), 26 `HistoryFilter`s, 8 Image history filters (window code,
  copied), `HistoryHelpers.OutputStats`, five `HistoryStats.Calculate` (with
  the calendar ranges and active days, peak hours, week start), `StatsFormat`
  (`Share`, `Number`, `Compact`, `HourSpan`), `StatsWindow.GetRate`,
  `StatsHourChart.GetScale`, `StatsCalendar.GetLevel`, the week change text
  and `HistoryColumnLayout.Load`/`ToSettings`.
- **Transactions:** whether `BeginTransaction()` keeps a second writer out
  (it does: `BEGIN IMMEDIATE`) and the journal mode.
- **Concurrent access:** each app appends while the other holds a write
  transaction for 2 s; both must wait and land.

`cases.json` is generated by `make_cases.py` (checked in). The files ShareX
wrote and what it read from them are also checked in as
`crates/sharex-history/tests/fixtures`, which `cargo test` compares with
dates pinned to London's rules, so CI checks them without .NET.
